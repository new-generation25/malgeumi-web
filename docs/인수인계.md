## 4. 자주 하는 작업

### 4-1. 새 공연 추가하기

`index.html`의 `#project` 섹션에서 `.show-card` 블록을 복사해 붙입니다.
그리드가 flex라 카드가 1개든 3개든 알아서 배치됩니다.

```html
<a class="show-card" href="공연페이지.html">
  <div class="show-card-thumb">
    <img src="images/포스터.jpg" alt="공연 포스터" loading="lazy" width="900" height="1118">
    <span class="show-card-badge">🎫 예매 중</span>
  </div>
  <div class="show-card-body">
    <h3>공연 제목</h3>
    <p class="show-card-meta"><i class="fa-regular fa-calendar"></i> 날짜 · 장소</p>
    <p class="show-card-desc">한 줄 소개</p>
    <span class="show-card-cta">자세히 보기 <i class="fa-solid fa-arrow-right"></i></span>
  </div>
</a>
```

- 썸네일 비율은 **4:5(세로)** 입니다. 세로 포스터가 잘리지 않게 맞춰둔 값입니다.
- 배지에 `is-upcoming` 클래스를 붙이면 흰 바탕(예정), 없으면 노란 바탕(예매 중)입니다.
- **끝난 공연은 카드를 지웁니다.** 진행하지 않는 공연을 남겨두면 어느 걸 예매해야 할지 헷갈립니다.

### 4-2. 이미지 넣기

원본을 그대로 올리지 말고 아래를 지킵니다.

```bash
# 크기 조정 + JPEG 변환 (ffmpeg 설치돼 있음)
ffmpeg -i 원본.png -vf "scale=1200:-2:flags=lanczos" -q:v 3 images/결과.jpg

# 특정 영역만 잘라내기 (crop=폭:높이:x:y)
ffmpeg -i 원본.png -vf "crop=900:1125:100:50,scale=1200:1500:flags=lanczos" -q:v 3 images/결과.jpg
```

**`<img>` 태그에는 반드시 `width`/`height`를 넣습니다.** 로딩 중 화면이 튀는 것을 막습니다.
화면 밖 이미지에는 `loading="lazy"`를, 첫 화면 이미지에는 `fetchpriority="high"`를 붙입니다.

> ⚠ **함정:** `width`/`height` 속성을 넣으면 CSS에 `img { height: auto }`가 반드시 있어야 합니다.
> 없으면 브라우저가 속성의 높이값을 그대로 적용해 이미지가 세로로 늘어납니다.
> 세 페이지 모두 넣어뒀지만, 새 페이지를 만들 때 빠뜨리기 쉽습니다.

## 5. 도메인 — 가장 자주 사고가 난 부분

**Vercel의 "프로젝트 이름"과 "도메인"은 별개입니다.** 프로젝트 이름을 바꿔도 도메인은 따라오지 않습니다.

도메인 변경 방법: Vercel 대시보드 → 프로젝트 → **Settings → Domains** → 새 주소 Add

### 도메인을 바꾸면 반드시 함께 고쳐야 하는 곳

절대주소가 하드코딩된 자리가 **5곳** 있습니다. 안 고치면 **카톡·인스타 공유 시 썸네일이 깨집니다.**

```bash
grep -rn "malgeumi-play.vercel.app" *.html
```

| 파일 | 항목 |
|---|---|
| index.html | `canonical`, `og:url`, `og:image` |
| king.html | `og:image` (주석 1곳 포함) |

기존 도메인을 **삭제하면 그 주소로 공유된 링크는 전부 죽습니다.** 새 주소를 추가한 뒤
기존 주소를 함께 두는 편이 안전합니다.

> 참고: 카카오톡은 OG 정보를 캐싱합니다. 깨진 채로 한 번 공유되면 고친 뒤에도 한동안 그대로 뜹니다.

## 6. 알아둘 제약

### 소식 구독 폼이 서버를 쓰지 않습니다

`index.html`의 구독 폼은 **방문자의 메일 앱을 여는 방식**(`mailto:`)입니다.
서버가 없어 입력 내용을 직접 받아 저장할 수 없습니다.

- 방문자 기기에 메일 앱이 설정돼 있지 않으면 **동작하지 않습니다**
- 특히 모바일에서 실패할 수 있습니다

→ **구글 폼을 만들어 링크로 교체하는 것을 권합니다.** 훨씬 안정적입니다.
(king.html의 예매 버튼은 이미 구글 폼 `forms.gle/BvXD3RBAWeCckMeQ7`을 씁니다.)

### 개인정보

구독 폼이 **휴대전화 번호를 받습니다.** 현재는 안내 문구만 있고 동의 체크박스가 없습니다.
실제로 문자 발송을 시작하면 **수집·이용 동의 체크박스를 추가해야 합니다.**

### 실존 인물 이미지

`king.html`의 이윤재(한뫼 이윤재, 1888~1943) 이미지는 **AI로 생성한 일러스트**입니다.
원래 기획 주석에는 "실존 인물, AI로 얼굴을 만들지 말 것 / 사료 사진 사용"이라고 적혀 있었습니다.
`alt`에 "(일러스트)"를 명시해뒀지만, **문제 제기 소지가 있는 항목**입니다.
공공누리 개방 사료 사진으로 교체하는 편이 안전합니다.

세종은 어진 재현 금지 때문에 **이미지 없이 텍스트만** 나갑니다. 의도된 상태입니다.

## 7. 디자인 규칙

### 네비게이션 — 세 페이지 완전 동일

색만 페이지 팔레트를 따르고 **크기·간격·위치는 픽셀 단위로 같습니다.**

```
패딩 16px 32px · 로고 24px/800 · 링크 간격 32px · 링크 15.2px
CTA 11.2px 28.8px, radius 9999px · 바 높이 81px
```

네비에는 **공통 시스템 폰트**를 씁니다. 페이지마다 본문 폰트가 달라(Noto Sans KR /
IBM Plex Sans KR / Pretendard) 같은 글자도 폭이 달라지기 때문입니다.
**네비 폰트를 페이지 폰트로 바꾸면 세 페이지의 메뉴 위치가 어긋납니다.**

모바일(768px 이하)에서는 햄버거 토글로 바뀝니다. 세 페이지 모두 같은 JS가 들어 있습니다.

### 본문 팔레트는 페이지마다 다릅니다 (의도된 것)

| 페이지 | 배경 | 강조색 | 성격 |
|---|---|---|---|
| index | `#F0F9FF` 밝은 하늘 | `#FFD700` | 밝고 친근 |
| king | `#0E1319` 어두운 잉크 | `#E8B54B` | 극의 톤 |
| theater | `#0F0D0B` 어두운 갈색 | `#E0AB60` | 아카이브 |

공연별로 자기 아트디렉션을 갖는 것은 공연예술 웹에서 일반적입니다.
브랜드는 **로고·네비·노랑~금색 계열 강조색**이 잇습니다.
