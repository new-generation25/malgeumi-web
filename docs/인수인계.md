## 2. 페이지 구성

```
index.html      회현동 소극장 — 랜딩(상단) + 소극장 상세(하단)를 한 파일에
malgeumi.html   말그미극단 소개
haeyeon.html    극단 해연 소개
king.html       「King받은 이도」 공연
join.html       대관 · 후원 — 책갈피 탭(#rental / #support)으로 한 페이지 안에서 이동
academy.html    배우고 참여하기 — 강좌·워크숍 게시판형 카드
```

**네비 "홈으로"는 여섯 페이지 전부 `index.html`을 가리킵니다.** 예전엔 페이지마다 제각각(자기
자신이거나, king.html은 malgeumi.html)이라 실제 홈으로 못 가는 버그였습니다 — 2026-08-26에
통일했습니다. 각 페이지의 로고(브랜드 마크)는 그대로 자기 자신을 가리킵니다.

### index.html의 두 구역

`index.html`은 **위아래로 목적이 다릅니다.**

- **상단(`.top`)** — 인스타그램·카카오톡 bio 링크를 대신하는 랜딩 구역입니다. 원래 리틀리
  (litt.ly/hoehyun.theater)를 쓰고 있었는데, 그걸 자체 페이지로 대체한 것입니다. 상단바(로고+전화) →
  히어로([A]/[B] 공연 유무 토글) → 이곳의 사람들(가로 스크롤 카드, 회현동소극장은 `#place`로
  같은 페이지 스크롤, 극단 해연·말그미극단은 각자 파일로) → 함께하기(아이콘 리스트) → 오시는 길 요약.
  섹션마다 강조색이 다릅니다 — 공연=앰버, 채널구독=카카오 옐로우, 이곳의 사람들=테라코타,
  함께하기=세이지그린, 오시는 길=앰버. 배경 자체는 계속 어두운 톤 하나로 유지해 산만하지
  않게 했습니다.
- **하단** (`#place`부터) — 원래 있던 소극장 상세 설명입니다. `#place`(우리가 선 자리) ·
  `#history`(여덟 해의 기록) · `#works`(무대의 이야기) · `#doing`(극장이 하는 일) · `#space`(공간) ·
  `#join`(함께하기 상세) · `#visit`(오시는 길 상세) · 푸터.

### 페이지 간 연결

```
index.html 상단 ──(이곳의 사람들)──▶ #place(같은 페이지) / haeyeon.html / malgeumi.html
                ──(함께하기 · 오시는 길)──▶ #join / #visit(같은 페이지)

index.html ──(네비)──▶ malgeumi.html · haeyeon.html · king.html
malgeumi.html ──(네비 '회현동소극장')──▶ index.html
haeyeon.html ──(네비)──▶ index.html · malgeumi.html
king.html ──(네비)──▶ malgeumi.html · index.html
```

`index.html · malgeumi.html · king.html · haeyeon.html` 네 페이지는 하단 콘텐츠 기준으로
**같은 네비 컴포넌트**(패딩·간격·CTA 수치 동일)를 쓰지만, 페이지마다 자기 브랜드를 걸고 있어
**메뉴 항목은 서로 다릅니다** (7절 참고). `index.html`의 상단(`.top`) 구역만 이 네비 CSS와
무관한 별도 디자인입니다(참고한 원본 코드 구조 그대로).

### malgeumi.html 섹션 순서

1. 히어로
2. `#philosophy` 활동 철학 — 극단 소개 문장 + 카드 3장 + 전문예술단체 지정 배지
3. `#project` 공연 안내 (카드 그리드 — 현재 King 1장)
4. `#archive` 지난 활동 (가로 스크롤 카드 5장 — 7-4 참고)
5. `#space` 회현동 소극장 (요약 + index.html 링크 + 네이버 지도 길찾기)
6. `#contact` 소식 구독 → 구글 시트
7. 푸터

### haeyeon.html 섹션 순서

히어로 · `#works`(대표작 — 동상동 아리랑·분장실) · 걸어온 길(연혁에서 해연 항목만 추림) · 함께하기(문의) · 푸터

> haeyeon.html은 index.html 하단(옛 theater.html)에 흩어져 있던 극단 해연 관련 사실만 모아
> 만들었습니다. **대표자·단원 소개는 원자료가 없어 비워 두었습니다.** 받으면 채워 넣으세요.

### 지난 활동에 쓰는 이미지

`work-*.jpg` 5장은 **4:5 세로**로 통일돼 있습니다 (900×1125).
카드 CSS가 `aspect-ratio: 4/5`라 다른 비율을 넣으면 잘립니다. 새로 추가할 때도 4:5로 맞추세요.

```bash
# 세로 포스터
ffmpeg -i 포스터.jpg -vf "crop=600:750:0:40,scale=900:1125:flags=lanczos" -q:v 3 images/work-이름.jpg
# 가로 공연사진 (가운데 피사체 기준으로 x 오프셋을 조절)
ffmpeg -i 사진.jpg -vf "crop=516:645:186:0,scale=900:1125:flags=lanczos" -q:v 3 images/work-이름.jpg
```

> ⚠ **모바일에서는 이 카드 이미지가 `aspect-ratio: 1/1`로 바뀝니다.** 4:5 그대로 두면 포스터에 본문까지
> 붙어 카드가 705px이 되어 한 화면에 안 들어갑니다. 세로를 낮춰 532px로 맞춰둔 것입니다.

`images/cert-252.jpg`는 전문예술단체 지정서입니다.
**원본에 대표자 생년월일이 찍혀 있어 흰 상자로 가린 판본**입니다. 원본으로 교체하지 마세요.

### 4-1. 제작 주체 페이지에 공연 카드 추가하기

말그미극단 공연이면 `malgeumi.html`의 `#project` 섹션에서 `.show-card` 블록을 복사해 붙입니다.
그리드가 flex라 카드가 1개든 3개든 알아서 배치됩니다.

```html
<a class="show-card" href="공연페이지.html">
  <div class="show-card-thumb">
    <img src="images/포스터.jpg" alt="공연 포스터" loading="lazy" width="900" height="1118">
    <span class="show-card-badge">🎫 예매 중</span>
  </div>
  <div class="show-card-body">
    <h3>공연 제목</h3>
    <p class="show-card-meta"><i class="fa-regular fa-calendar"></i> 날짜 · 장소</p>
    <p class="show-card-desc">한 줄 소개</p>
    <span class="show-card-cta">자세히 보기 <i class="fa-solid fa-arrow-right"></i></span>
  </div>
</a>
```

- 썸네일 비율은 **4:5(세로)** 입니다. 세로 포스터가 잘리지 않게 맞춰둔 값입니다.
- 배지에 `is-upcoming` 클래스를 붙이면 흰 바탕(예정), 없으면 노란 바탕(예매 중)입니다.
- **끝난 공연은 카드를 지웁니다.** 진행하지 않는 공연을 남겨두면 어느 걸 예매해야 할지 헷갈립니다.

극단 해연 공연이면 `haeyeon.html`의 `#works` 섹션에서 `.work` 블록을 복사해 붙입니다
(카드 그리드가 아니라 세로로 쌓이는 구조입니다).

### 4-3. 이미지 넣기

원본을 그대로 올리지 말고 아래를 지킵니다.

```bash
# 크기 조정 + JPEG 변환 (ffmpeg 설치돼 있음)
ffmpeg -i 원본.png -vf "scale=1200:-2:flags=lanczos" -q:v 3 images/결과.jpg

# 특정 영역만 잘라내기 (crop=폭:높이:x:y)
ffmpeg -i 원본.png -vf "crop=900:1125:100:50,scale=1200:1500:flags=lanczos" -q:v 3 images/결과.jpg
```

화면 밖 이미지에는 `loading="lazy"`를, 첫 화면 이미지에는 `fetchpriority="high"`를 붙입니다.

로딩 중 화면이 튀지 않게 **자리를 미리 잡아둬야** 합니다. 페이지마다 방법이 다릅니다.

| 페이지 | 방법 |
|---|---|
| malgeumi.html, index.html(하단), haeyeon.html | `<img>`에 `width`/`height` 속성 |
| **king.html** | CSS `aspect-ratio` (`figure img{aspect-ratio:3/2}` 등) |

king.html의 `<img>`에는 `width`/`height`가 없습니다. **일부러 그런 것이니 넣지 마세요.**
CSS가 이미 비율을 잡고 있어서, 속성을 추가하면 오히려 충돌합니다.

> ⚠ **함정:** `width`/`height` 속성을 쓰는 페이지는 CSS에 `img { height: auto }`가 반드시 있어야 합니다.
> 없으면 브라우저가 속성의 높이값을 그대로 적용해 이미지가 세로로 늘어납니다.
> malgeumi.html(102행)과 index.html, haeyeon.html에 들어 있습니다. 새 페이지를 만들 때 빠뜨리기 쉽습니다.

도메인 변경 방법: Vercel 대시보드 → 프로젝트 → **Settings → Domains** → 새 주소 Add

### 도메인을 바꾸면 반드시 함께 고쳐야 하는 곳

절대주소가 하드코딩된 자리가 **네 파일 × 3곳 = 12곳** 있습니다. 안 고치면 **카톡·인스타 공유 시 썸네일이 깨집니다.**

```bash
grep -rn "malgeumi-play.vercel.app" *.html
```

| 파일 | 항목 |
|---|---|
| index.html (랜딩) | `canonical`, `og:url`, `og:image` |
| malgeumi.html | `canonical`, `og:url`, `og:image` |
| haeyeon.html | `og:url`, `canonical`, `og:image` |

기존 도메인을 **삭제하면 그 주소로 공유된 링크는 전부 죽습니다.** 새 주소를 추가한 뒤

### 소식 구독 폼 — 구글 시트로 들어갑니다

**두 곳에 있습니다.** `malgeumi.html #contact`의 원래 구독 폼과, `index.html` 상단([B] 공연 없을 때
"문자로 공연 알림 받기" 버튼을 누르면 뜨는 팝업)의 구독 폼입니다. **같은 Apps Script 웹앱, 같은
시트**로 씁니다 — 목록을 두 개로 나누지 않으려고 일부러 그렇게 했습니다. 웹앱 주소를 바꾸면
`malgeumi.html`의 `SHEET_ENDPOINT`와 `index.html`의 `SHEET_ENDPOINT` **둘 다** 고쳐야 합니다.

`malgeumi.html`의 구독 폼은 입력 내용을 **구글 시트에 한 줄씩 기록**합니다.
홈페이지가 시트에 직접 쓰는 게 아니라, 시트에 붙어 있는 **Apps Script 웹앱**이 중간에서 받아 적습니다.

```
방문자 → malgeumi.html 구독 폼 → Apps Script 웹앱 → 구글 시트
                (fetch POST)        (시트 주인 권한으로 실행)
```

| 항목 | 값 |
|---|---|
| 시트 | 「말그미극단 소식 구독자 명단」 (`hoehyeon.theater@gmail.com` 소유) |
| 시트 주소 | https://docs.google.com/spreadsheets/d/1S8vb0Thx2P7-Wh1CQxV8TrU1zntcjrbitF27YJrczEw/edit |
| 스크립트 | [docs/구독폼-AppsScript.gs](구독폼-AppsScript.gs) — 배포된 것과 같은 내용을 보관 |
| 웹앱 주소 | `malgeumi.html`의 `SHEET_ENDPOINT` 상수 |

**시트는 비공개로 두세요.** 이름과 휴대전화 번호가 쌓입니다. 공유하지 않아도 기록은 정상 동작합니다 —
스크립트가 시트 주인 권한으로 돌기 때문입니다.

#### 스크립트를 고쳐야 할 때

`.gs` 파일만 고치면 **반영되지 않습니다.** 시트 → 확장 프로그램 → Apps Script 에서 고친 뒤
**배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포** 해야 합니다.
이렇게 하면 웹앱 주소는 그대로 유지됩니다. "새 배포"를 누르면 **주소가 바뀌어**
`malgeumi.html`의 `SHEET_ENDPOINT`도 함께 고쳐야 합니다.

#### 주소가 비어 있으면

`SHEET_ENDPOINT`가 빈 문자열이면 **예전 방식(메일 앱 열기)으로 자동 전환**됩니다.
웹앱을 다시 배포하는 동안 사이트가 멈추지 않게 해둔 장치입니다.

#### 신청이 끝나면 팝업이 뜹니다

`<dialog id="subscribeDone">`이 화면 가운데에 "구독이 완료되었습니다"를 띄웁니다.
확인 버튼·배경 클릭·Esc로 닫힙니다. `<dialog>`를 못 쓰는 오래된 브라우저에서는
폼 아래 초록 글씨로 대신 알립니다.

> ⚠ **버튼 상태 복구는 `finally`에 있습니다.** 예전에 성공 경로에서만 빠져 있어
> 신청은 정상으로 들어가는데 버튼이 '보내는 중…'에 멈춰 있었습니다. 옮기지 마세요.

> ⚠ **팝업 위치**: 맨 위 `* { margin: 0 }`이 `dialog`의 기본 가운데 정렬(`margin: auto`)을
> 덮어버립니다. `.modal`에서 `margin: auto`로 되돌려 놨습니다. 지우면 팝업이 화면
> 좌상단에 붙습니다.

### 개인정보

구독 폼이 **휴대전화 번호를 받습니다.** 수집·이용 **필수 동의 체크박스**가 있고,
체크하지 않으면 제출이 막힙니다. 스크립트도 `consent=y`가 아닌 요청은 **기록하지 않습니다** (이중 방어).

동의 여부와 **서버 기준 시각**이 시트에 함께 남습니다. 방문자가 고칠 수 없는 기록이라
개인정보보호법이 요구하는 동의 입증 자료로 쓸 수 있습니다.

문자 발송을 시작하면 동의와 별개로 아래도 지켜야 합니다 (정보통신망법).

- 문자 맨 앞에 **(광고)** 표기
- 무료 수신거부 수단 안내
- **21시~08시 발송 금지** (야간 수신동의를 따로 받지 않았다면)
- **2년마다** 수신동의 여부 재확인

동의 문구를 고칠 때는 `malgeumi.html`의 `.consent-detail` 문단과 위 문서를 함께 고치세요.

### 실존 인물 이미지

### 지난 활동 가로 스크롤 — 건드릴 때 주의

`#archive`는 옆으로 넘겨 보는 목록입니다. **옆에 더 있다는 걸 알리는 장치가 셋** 들어 있고,
하나라도 빠지면 방문자가 카드가 더 있는 줄 모릅니다.

| 장치 | 어디에 |
|---|---|
| 다음 카드가 살짝 걸침 | 모바일에서 카드 `74vw`, 스크롤러에 `margin-inline: -2rem` |
| 양끝 페이드 | `.archive-viewport::before/::after` + JS가 `can-prev`/`can-next` 토글 |
| 좌우 화살표 | `.archive-nav` (모바일에서는 포스터를 가려 숨김. 대신 안내 문구 한 줄) |

주의할 점:

- **`margin-inline: -2rem`이 섹션 밖으로 삐져나가 페이지에 가로 스크롤을 만듭니다.**
  모바일 미디어쿼리의 `#archive { overflow-x: hidden }`이 그걸 잘라줍니다. 지우지 마세요.
- 화살표 클릭은 `scrollBy`에 **안전장치**가 붙어 있습니다. `scroll-snap` 컨테이너에서 smooth
  스크롤을 취소하는 브라우저가 있어서, 350ms 뒤에도 안 움직였으면 그냥 옮깁니다.
- 화살표 상태는 `scroll` 이벤트뿐 아니라 **버튼 쪽에서도 갱신**합니다. 한쪽만 믿으면 화살표가
  끝에 닿아도 안 사라집니다.

### 지도 — 네이버 Dynamic Map

`#space`에 **진짜 네이버 지도**가 들어갑니다. 끌어서 움직이고 확대·축소됩니다.
오른쪽 아래 `길찾기` 버튼을 누르면 네이버 지도 플레이스로 나갑니다.

| 항목 | 값 |
|---|---|
| 콘솔 Application | `malgeumi-web` (네이버 클라우드 플랫폼) |
| Client ID | `ywa9tndcag` — `malgeumi.html`의 `NAVER_KEY` 상수 |
| 좌표 | `35.232767, 128.8744441` — `malgeumi.html`의 `SPOT` 상수 |
| 플레이스 | https://map.naver.com/p/entry/place/1044803603 |
| 콘솔 | https://console.ncloud.com/maps/subscription |

**비용은 들지 않습니다.** Dynamic Map 무료 이용량이 월 600만 건이고 계정 단위로 공유됩니다.
같은 계정에 `bonghwang-memories` 등 다른 앱이 있지만 키는 앱마다 따로입니다.

> ⚠ **도메인이 등록된 곳에서만 뜹니다.** 콘솔의 이 Application → 서비스 환경 등록 →
> Web 서비스 URL에 `https://malgeumi-play.vercel.app`과 `http://localhost:8765`가 들어 있습니다.
> **도메인을 바꾸면 여기도 추가해야 합니다.** 안 하면 `navermap_authFailure`가 나고 지도가 안 뜹니다.

#### 안 떠도 사이트는 안 깨집니다

키가 틀리거나 도메인이 안 맞거나 네이버가 죽으면, **예전 지도 이미지(`images/map.jpg`)가
그대로 남고** 누르면 네이버 지도로 나갑니다. `.map-box`에 `is-live`가 붙어야 지도로 바뀝니다.

#### 좌표를 다시 구해야 한다면

플레이스 페이지에는 **주변 장소들의 좌표가 여럿 섞여 있습니다.** 아무거나 짝지으면 엉뚱한 데
찍힙니다(처음에 수로왕릉역에 찍혔습니다). 아래처럼 극장 자신의 `coordinate` 항목만 뽑으세요.
`x`가 경도, `y`가 위도입니다.

```bash
curl -s -A "Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X)" \
  "https://m.place.naver.com/place/1044803603/home" \
  | grep -oE '"coordinate":\{[^}]{0,120}'
```

구한 좌표는 반드시 역지오코딩으로 검산하세요. **김해도서관**이 나와야 맞습니다.

#### 마커는 핀이 아니라 이름표입니다

기본 핀을 쓰면 확대했을 때 그 자리의 다른 상호에 묻힙니다. 그래서 `.map-pin` 클래스를 쓴
HTML 이름표("회현동 소극장")를 마커 아이콘으로 넣습니다.

**`.map-pin` CSS를 지우면 마커가 맨 글씨로 나옵니다.** 이 규칙은 지도 안에 심어지는
요소를 꾸미는 것이라, 페이지 어디에서도 쓰지 않는 것처럼 보여도 지우면 안 됩니다.

#### 손볼 때 걸린 두 가지 함정

- **지도를 `display:none` 상태에서 만들면 빈 화면이 됩니다.** 컨테이너 크기가 0이라서입니다.
  그래서 `is-live`를 먼저 붙여 보이게 한 뒤 `new naver.maps.Map(...)`을 부릅니다. 순서를 바꾸지 마세요.
- **네이버 API가 컨테이너의 `position`을 `relative`로 덮어씁니다.** `.map-live`에 `absolute; inset:0`으로
  크기를 주면 높이가 0이 됩니다. `width/height: 100%`로 지정해야 합니다.

스크립트는 **지도가 화면에 들어올 때만** 불러옵니다(IntersectionObserver). 아래까지 안 내려가는
방문자에게는 요청 자체가 나가지 않습니다.

`images/map.jpg`는 이제 대체용으로만 쓰입니다.

### 구독 폼 CSS — 건드릴 때 주의

`malgeumi.html`의 폼 규칙은 `.contact-form input:not([type="checkbox"])` 로 시작합니다.
`:not()`을 지우면 동의 체크박스가 `padding: 1rem`을 물려받아 **거대한 상자로 렌더됩니다.**
폼에 새 `input` 규칙을 추가할 때도 체크박스를 함께 제외했는지 확인하세요.

체크박스에 `color-scheme: light`가 걸려 있습니다. 지우면 **OS 다크 모드에서 체크박스가 보이지 않습니다**
(어두운 체크박스가 짙은 남색 배경 위에 놓임). `appearance: none`으로 커스텀 디자인하는 것도 금물입니다 —
크롬이 아무 메시지 없이 제출을 거부해, 버튼을 눌러도 아무 일이 일어나지 않게 됩니다.

### 관리자 자기 방문 제외

홈페이지를 고치며 새로고침한 것, 확인하려고 눌러 본 것까지 GA는 전부 방문으로 셉니다.
개편 초기에 «예매하기 전환율 35%» 같은 수치가 나온 것이 그 때문입니다.

**끄는 법** — 주소 끝에 `?noanalytics=1` 을 붙여 한 번 열면 됩니다.

```
https://malgeumi-play.vercel.app/?noanalytics=1     제외 시작
https://malgeumi-play.vercel.app/?noanalytics=0     다시 포함
```

화면 아래에 «이 브라우저는 통계에서 제외됩니다» 라고 잠깐 뜨면 걸린 것입니다.
그 뒤로는 어느 페이지를 돌아다녀도 GA와 Vercel 어느 쪽에도 기록되지 않습니다.

| 항목 | 어떻게 막나 |
|---|---|
| GA4 | `window['ga-disable-G-LGQHMEV50C'] = true` — 구글이 정한 차단 스위치 |
| Vercel | `va('beforeSend', () => null)` — Vercel 문서가 opt-out 예시로 드는 방식 |

> **표시는 브라우저에 남습니다**(`localStorage`의 `analytics-off`). 따라서
> **기기·브라우저마다 한 번씩** 해줘야 합니다. 사무실 PC, 집 PC, 휴대폰이 각각입니다.
> 시크릿 창이나 «사이트 데이터 삭제»를 하면 풀립니다.

> IP로 막는 방법(GA 내부 트래픽 정의)도 있지만, IP가 바뀌거나 밖에서 접속하면
> 소용이 없습니다. 브라우저 표시 방식을 쓴 이유입니다.

**이미 쌓인 데이터는 지울 수 없습니다.** GA는 소급 삭제를 지원하지 않습니다.
2026-08-26 이전 수치는 개발 트래픽이 섞인 것으로 보고 읽으세요.

### 자체 대시보드

여러 사이트의 GA4 지표를 **한 화면**에 모읍니다. 정적 사이트에 Vercel 서버리스 함수를 하나 얹은 구조입니다.

lib/sites.js        대시보드에 띄울 사이트 목록

**필요한 환경변수** (Vercel → Settings → Environment Variables)

| 항목 | 값 |
|---|---|
| 프로젝트 | `malgeumi-analytics` |
| 사용 설정한 API | Google Analytics Data API |
| 서비스 계정 | `dashboard-reader@malgeumi-analytics.iam.gserviceaccount.com` |

`GA_SA_EMAIL`은 **서비스 계정 주소**입니다. 사람 계정(`socialceos@gmail.com`)을 넣으면
구글이 `Invalid grant: account not found`로 답합니다. 한 번 겪었습니다.

비공개 키를 잃어버렸으면 GCP에서 **새 키를 발급**하면 됩니다(키 여러 개 공존 가능, 옛 키는 폐기).
받은 JSON 파일은 이 저장소 폴더에 두지 마세요. `.gitignore`가 `*.json`을 막고 있지만,
공개 저장소 폴더 안에 키를 두는 것 자체가 위험합니다.

**사이트를 추가하려면**

1. `lib/sites.js`에 항목 하나 추가 (`propertyId`는 비밀이 아니라 커밋해도 됩니다)
2. 그 GA 속성의 **관리 → 속성 액세스 관리**에서 서비스 계정 이메일을 **뷰어**로 추가

2번을 빼먹으면 대시보드에 그 사이트만 «권한 없음»으로 뜹니다. 나머지는 정상 동작합니다.

**한 사이트의 특정 페이지만 따로 보려면** 항목에 `path`를 주면 됩니다. 지금 다섯 페이지가
그렇게 등록돼 있습니다 (`lib/sites.js`).

```
whole      회현동 소극장 홈페이지 (전체)   ← path 없음. 속성 전체
index      첫 페이지                    /
king       King받은 이도                /king.html
malgeumi   말그미극단                   /malgeumi.html
haeyeon    극단 해연                    /haeyeon.html
```

```js
{ id: 'king', label: 'King받은 이도',
  url: 'https://malgeumi-play.vercel.app/king.html',
  propertyId: '551060035', path: '/king.html' },
```

`id`는 겹치면 안 됩니다. 대시보드가 `id`로 카드를 고르기 때문에, 겹치면 엉뚱한 카드가
열립니다. 전체 항목과 `malgeumi.html` 항목이 둘 다 `malgeumi`였던 적이 있습니다.

> ⚠ **2026-08-25 개편으로 `/` 경로의 의미가 바뀌었습니다.** 그 전에는 `/`가 말그미극단
> 메인(지금의 malgeumi.html)이었는데, 지금은 랜딩페이지입니다. 개편 이전 `/` 데이터와
> 이후 `/` 데이터를 같은 그래프로 이어 보면 다른 페이지를 하나로 잘못 읽게 됩니다.
> 개편 시점을 기준으로 나눠 보세요.

주의할 것 둘입니다.

- 페이지 항목은 전체 항목과 **같은 데이터를 잘라 본 것**입니다. 화면 상단 합계는
  `path`가 없는 항목만 더합니다. 함께 더하면 같은 방문을 두 번 셉니다.
- GA 실시간 보고서는 `pagePath` 필터를 지원하지 않아, 페이지 항목에는
  «지금 접속 중»이 나오지 않습니다. 일부러 비워 둔 것입니다.

> **함정 — 환경변수 입력칸이 키를 망가뜨립니다.** 실제로 겪은 것만 넷입니다.
> 줄바꿈이 `
` 두 글자로 바뀜 · 공백으로 바뀜 · 아예 사라짐 · `-----BEGIN/END-----` 줄을
> 지우고 본문만 넣음. 어느 쪽이든 Node가 `error:1E08010C:DECODER routines::unsupported`를 냅니다.
> `lib/ga.js`가 전부 복구하도록 해뒀지만, **붙여넣을 때는 BEGIN부터 END까지 통째로** 넣으세요.
>
> **Vercel의 Edit은 값을 이어받지 않습니다.** 누르면 입력칸이 빈 채로 열리고, 거기서 저장하면
> 방금 친 것만 들어갑니다. 고치려면 값 전체를 다시 넣거나, 지웠다 새로 만드세요.
